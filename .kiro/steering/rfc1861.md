# RFC 1861 — SNPP level 3, the parts we implement

Source: <https://www.rfc-editor.org/rfc/rfc1861.txt> (October 1995). The gateway
listens on `127.0.0.1:4440` by default; the historical port 444 is privileged
and the protocol is plaintext, so it is never exposed to the Internet.

## Commands accepted

| Command | Effect in Beeper |
|---|---|
| `2WAY` | Opens a two-way decision request |
| `PAGEr <id>` | Selects the pager: `850` when online, `950` when the request will be queued |
| `MESSage <text>` | The page line — one single line, as the RFC wants |
| `RTYPe YESNO \| MULTICHOICE` | Expected reply type |
| `MCREsponse <code> <text>` | Seeds one possible reply (up to four) |
| `ACKRead 1` | Requests a read acknowledgement |
| `EXPTag <hours>` | Lifetime of the page |
| `SEND` | Fires the page; answers `861 <tag> <secret>` |
| `MSTAtus <tag> <secret>` | `861` delivered, `870` read, `888` reply received with its code, `780` expired |
| `KTAG <tag> <secret>` | Releases the tag |
| `RESEt` | Abandons the current transaction |
| `QUIT` | Closes the session |
| `HELP` | Lists the accepted commands |
| `LOGIn <id> <password>` | Required outside the loopback |

## Answer codes used

`220` service ready · `250` OK · `850` two-way unit online · `861` delivered,
awaiting reply · `870` read acknowledgement · `888` reply received ·
`950` transaction queued · `780` expired · `501` syntax error ·
`503` bad sequence (command not valid in this state) · `421` service closing.

## Rules for the implementation

1. The parser **never throws**: any input line produces an RFC code
   (property BIP-P-11).
2. Commands are matched case-insensitively on their four-letter prefix, exactly
   as the RFC writes them (`MESSage`, `RTYPe`, `MCREsponse`, `MSTAtus`, …).
3. A command out of sequence answers `503`, it does not corrupt the transaction.
4. One transaction = one page. `RESEt` and `QUIT` release every tag held by the
   session; a closed socket does the same.
5. The message is a single line: a CR or LF inside `MESSage` ends the command.
6. The gateway never invents a reply code: every code it sends appears in the
   table above, and `docs/SNPP.md` keeps a full transcript that a test replays.
